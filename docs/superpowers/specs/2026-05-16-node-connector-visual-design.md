# Node Connector Visual Design

## Goal

在不改变节点本体样式、编辑交互、拖拽行为、保存加载逻辑的前提下，仅调整思维导图中指定场景的连线样式与分叉布局，使其贴近用户提供的参考图：

- 单个节点连接单个节点时，连线保持一条纯直线
- 单个词节点连接单个节点时，连线同样保持一条纯直线
- 一个节点连接多个子节点时，使用共享主干后再分叉的布局，而不是每条边各自独立从父节点发散

## Scope

本次修改只覆盖视觉层的连线组织方式与分叉布局。

允许修改：

- `lib/utils/g6.ts` 中的边类型选择逻辑
- `lib/utils/g6.ts` 中的父子连线端口选择逻辑
- `lib/utils/g6.ts` 中的多子节点分叉布局逻辑
- 与上述逻辑直接相关的测试文件

明确不修改：

- 节点矩形形状、颜色、圆角、字体、字号、边框
- 节点内容编辑、聚焦、拖拽、排序、删除、折叠/展开
- MindMap 数据结构
- 保存、导出、API、LLM、摘要、解析相关逻辑

## Current Behavior

当前实现位于 `lib/utils/g6.ts` 与 `components/mindmap-editor.tsx`：

- 单子节点场景会根据端口位置直接输出 `line`
- 多子节点场景会按每条边分别输出 `line` 或 `polyline`
- 多子节点之间没有显式的“共享主干”概念，而是让每条边独立从父节点的出端口连接到目标节点

这导致两个与参考图不一致的问题：

1. 多子节点场景中，兄弟节点的边缺少统一的分叉主干，视觉上不像一组分支
2. 部分场景会出现单边独立判断，无法稳定复现“父节点出线后统一分叉”的结构

## Target Visual Rules

### 1. 单个节点

当父节点只有一个子节点，且该关系不涉及兄弟分叉时：

- 连线必须是一条单段直线
- 不插入中间主干
- 不做额外正交折线路由

### 2. 单个词节点

“单个词节点”不引入新的节点样式规则，只作为单节点场景的一种内容长度特例处理：

- 仍走单节点直线规则
- 不能因为文本过短而触发不同的连线布局
- 节点宽度仍由现有 `getNodeSize()` 负责，不在本次视觉改动中重写

### 3. 一个节点与多个子节点

当父节点有多个子节点时，连线布局应遵循参考图：

- 所有子节点共享父节点右侧的一根短主干
- 主干上按照子节点的纵向位置分叉
- 每个子节点从主干横向接出
- 父节点到主干之间保留一小段短水平线
- 不允许每条子边各自独立从父节点右侧直接发散

## Layout Strategy

### Recommended Approach

保留现有 G6 节点布局，仅重构运行时边布局决策。

具体策略：

1. 继续使用当前节点位置结果作为最终节点坐标来源
2. 对每个父节点按 `childrenByParent` 分组处理子边
3. 当 `childIds.length === 1` 时，直接输出纯直线
4. 当 `childIds.length > 1` 时，为这组兄弟边生成统一分叉结构

### Shared Trunk Model

对一个拥有多个子节点的父节点：

1. 取父节点出端口作为起点
2. 在父节点右侧固定距离处定义一个“分叉主干 X”
3. 主干在垂直方向覆盖该组子节点的最上与最下连接点
4. 每个子节点从主干处水平连接到自己的入端口

这意味着视觉上应形成：

- 一条父节点到主干的短水平线
- 一条纵向主干线
- 多条从主干到子节点的水平支线

该结构应递归适用于子节点继续拥有多个后代的情况。

## Implementation Boundaries

### File 1: `lib/utils/g6.ts`

这里是本次主要实现点。

需要增加或调整的职责：

- 抽出“单节点直线”和“多子节点共享主干”两种边布局分支
- 将多子节点场景从“逐边独立判断”改为“按父节点成组判断”
- 为共享主干场景生成一致的端口/路径配置

不在此文件中做的事情：

- 不改节点尺寸算法
- 不改文本换行规则
- 不改编辑器事件

### File 2: `tests/g6-position.test.ts`

这里补充与收紧测试，确保：

- 单节点场景输出纯直线
- 单词节点场景输出纯直线
- 一个父节点接多个子节点时，边布局按照共享主干组织
- 子节点继续带子节点时，共享主干规则能够递归成立

### Optional File 3: `tests/mindmap-editor-styles.test.ts`

如果现有测试仍直接依赖旧的 `polyline` 假设，则需要把断言调整为“共享主干布局”而非“每条边独立正交折线”。

## Test Matrix

### A. 节点显示准确性测试

- 节点形状、填充色、边框、字号不发生变化
- 单词节点与普通节点仅内容长度不同，外观规则一致

### B. 连线关系正确性测试

1. 一个父节点连接一个普通子节点
   - 预期：纯直线

2. 一个父节点连接一个单词子节点
   - 预期：纯直线

3. 一个父节点连接两个子节点
   - 预期：共享主干后分叉

4. 一个父节点连接四个子节点
   - 预期：共享主干后分叉，所有兄弟边从同一主干发出

5. 一个父节点连接多个子节点，其中某个子节点再连接一个子节点
   - 预期：上一层共享主干，下一层单子节点为纯直线

6. 一个父节点连接多个子节点，其中某个子节点再连接多个子节点
   - 预期：上一层共享主干，下一层继续共享主干

### C. 布局兼容性测试

- 主验证方向：`LR`
- 烟测方向：`RL`、`TB`、`BT`
- 要求不出现边丢失、路径反向、节点遮挡主干、明显交叉错位

### D. 集成测试

- 编辑节点文字后重渲染，连线布局保持正确
- 拖拽节点后重渲染，连线布局保持正确
- 保存并刷新页面后，连线布局保持正确
- 切换布局方向后，连线布局保持正确

## Risks

1. 现有 `polyline` 逻辑与新的“共享主干”概念存在差异，若直接复用旧判断，容易得到“每条边独立折线”而不是“整组兄弟共享主干”
2. 多方向布局下，主干的坐标基准需要随方向切换，否则 `RL/TB/BT` 会出现镜像或反向问题
3. 如果把主干布局写进节点坐标而不是边坐标，会扩大影响范围，不符合最小改动原则

## Final Recommendation

采用“保留现有节点布局，仅重构运行时边布局”的方案：

- 单子节点：纯直线
- 多子节点：共享主干分叉
- 节点样式与交互不变
- 只修改 `lib/utils/g6.ts` 与直接相关测试

这是满足参考图视觉特征、同时对现有系统侵入最小的实现路径。
